The Decision Engine

Where Does Jev Fit?

The Jev-style layer acts as the decision and classification layer between the merchant's natural-language request and the specialized business workflows.

Instead of executing slow, non-deterministic language models for simple routing, Jev classifies requests across strongly typed Choice categories at micro-latency, outputting both the intent and a calibrated certainty score.

💡 Why is this revolutionary? We decouple categorization from computation. The classifier only determines what the merchant wants; pure Python math handles the truth.

Architectural Safety Guardrail

Understanding Is Not Enough.
The System Must Know How Confident It Is.

The confidence router prevents the system from blindly executing operations on uncertain or ambiguous queries.

CLEAR (94% Conf)

"Show my best-selling products"

Unambiguous semantic overlap with Product catalog choice.

Confidence: 0.94 ≥ 0.70 → Products Node
MODERATE (78% Conf)

"How are my sales doing?"

General inquiry, clearly mapped to the Analytics domain.

Confidence: 0.78 ≥ 0.70 → Analytics Node
AMBIGUOUS (45% Conf)

"Tell me about my business"

Vague input; no single dominant intent detected.

Confidence: 0.45 < 0.70 → Support & Clarify

The 0.70 Confidence Decision Gate

If confidence ≥ 0.70, the state progresses to the specialized node. Otherwise, the gate routes to support_node for guided clarification.

≥ 0.70 : Execute Intent Node
< 0.70 : Divert to Support

The Integrity Rule

AI Decides. Data Calculates.

In business systems, arithmetic mistakes destroy trust. The classifier determines "What does the merchant want to know?" but the factual calculations are calculated with pure, unyielding Python logic:

✓

Zero Numerical Hallucinations: The LLM is strictly prohibited from inventing rupee figures, inventory counts, or percentage deltas.

✓

Deterministic Formulae: Period-over-period revenue comparisons ($\Delta = -44.68\%$) are calculated before any text synthesis occurs.

✓

Optional Downstream LLM: When enabled, an LLM only polishes and summarizes the deterministic numbers into natural conversational phrasing.

Architecture Separation of Concerns

STEP 1: INTENT CLASSIFICATION (Jev / TF-IDF)
Input: "Why were sales low yesterday?" → Intent: ANALYTICS (0.94)
STEP 2: ROUTING (LangGraph StateGraph)
Router Node → Routes execution to analytics_node
STEP 3: DETERMINISTIC MATH (Python)
(₹31,200 - ₹56,400) / ₹56,400 → -44.68% Drop (Computed Exactly)
STEP 4: FINAL SYNTHESIS
"Yesterday (2026-10-01), revenue was ₹31,200 (a 44.7% drop)..."

Architectural Advantage

Why Not Just Send Everything to an LLM?

Comparing the monolithic LLM approach versus the Merchant Intelligence Router architecture.

Naïve Approach: Monolithic LLM Prompt
  • ✗ High Hallucination Risk: The LLM invents financial metrics and stock counts when calculating math in natural language tokens.
  • ✗ High Latency & Token Bills: Every single query runs through large token generation pipelines ($$$).
  • ✗ No Confidence Guardrails: Ambiguous questions still execute with hallucinations rather than asking for clarification.
  • ✗ Hard to Debug: Black-box execution without discrete inspectable state transitions.
Merchant Intelligence Router Architecture
  • ✓ Zero-Hallucination Math: Deterministic Python algorithms compute all revenue % deltas and rankings.
  • ✓ Sub-Millisecond Classification: Jev-style layer categorizes requests in micro-seconds at ₹0 cost.
  • ✓ Confidence Guardrails: 0.70 threshold automatically catches ambiguity and safely asks for clarification.
  • ✓ Inspectable LangGraph: Every node, transition, and state mutation is 100% testable with pytest.

• Decision Engine : Jev-Compatible Classifier (BaseIntentClassifier)
